## ⚠️ 先说清楚

这是一个**纯练习项目**。

SimpleHR（简人系统）里的公司、员工、考勤规则、报销单全部是 AI 虚构的，不是真实业务，也没有真实数据。它存在的唯一目的，是给测试新人提供一个「能跟着动手」的完整项目场景——从接活摸底一路做到上线复盘。

代码和文档都以「讲清楚测试思路」为第一目标，UI 只保证可用，不追求好看。

## 这个项目在测什么

SimpleHR 是虚构公司「简好科技」（约 200 人）内部使用的人事考勤与报销系统，覆盖员工每天的三件高频事：**打卡、请假、报销**。

```
员工每天打卡
   │
   ├── 缺卡 ──► 补卡申请 ──┐
   ├── 有事 ──► 请假申请 ──┤
   ├── 加班 ──► 加班申请 ──┼──► 通用审批流 ──► 通过 / 驳回 / 撤回
   │                       │         │
   │                       │         └──► 报销单 ──► 待打款 ──► 已打款
   └───────────────────────┘
```

本期重点考察四块硬骨头：

| 难点 | 具体体现在 |
| --- | --- |
| ⏱ 时间边界 | 迟到 5 分钟宽限、夜班跨天归属、跨月考勤统计 |
| 🔁 状态机 | 分级审批、自审跳过、并发审批、驳回重提 |
| 💰 金额与额度 | 发票号防重、月累计额度、金额精度（按分存储） |
| ⚡ 非功能 | 打卡高峰 08:50-09:10 的 100 并发压测 |

## 怎么用这个仓库

**只想看思路**：直接读 `articles/` 里的文章，按顺序读下来就是一条完整的测试工作流。

**想边看边练**：

```bash
git clone <SimpleHR-Demo 仓库地址>      # 1. 拉起被测系统
cd SimpleHR-Demo && 按 README 启动服务   # 2. 本地跑起来
git checkout ch02                       # 3. 切到对应章节 tag 拿配套资料
```

每篇文章结尾会写明「本期产出落在哪个目录」，按 tag 找就不会版本错乱。
