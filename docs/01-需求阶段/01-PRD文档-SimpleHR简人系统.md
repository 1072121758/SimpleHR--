# SimpleHR 简人系统 · 产品需求文档（PRD · 最终确认版）

> 版本：V2.0（两轮需求评审后定稿）
> 日期：2026-09-30
> 状态：已评审通过，开发排期中
> 系统定位：一家虚构公司（简好科技公司，约 200 人）内部使用的人事考勤与报销系统

## 一、项目背景

SimpleHR（简人系统）是简好科技的内部人事系统，覆盖员工日常三件高频事：**每天打卡、有事请假、花钱报销**。这三件事背后是一条完整的业务链：考勤规则 → 打卡数据 → 请假/补卡/加班申请 → 审批流 → 报销打款。

定位说明：

- 内部管理系统，员工 PC 端 + 手机浏览器均可访问（不做原生 App）
- 本期核心是把「考勤规则判定 + 审批流状态机 + 报销财务合规」三条主线跑通
- 重点考察典型业务难点：时间边界判定、跨天场景、额度扣减、分级审批、并发审批、防重复报销
- UI 只保证可用，重点在业务规则正确性

## 二、角色与权限

| 角色 | 编码 | 权限说明 |
| --- | --- | --- |
| 超级管理员 | super_admin | 全部功能，含基础配置、审批流规则 |
| HR | hr | 考勤管理、假勤调整、全员考勤报表、审批流配置 |
| 财务 | finance | 报销单审核打款、发票查验、报销报表 |
| 部门管理员 | dept_admin | 本部门考勤查看、作为默认审批人处理下级申请 |
| 普通员工 | employee | 打卡、查看本人考勤、发起请假/补卡/加班/报销、处理自己作为审批人的单子 |

说明：审批人身份由「组织架构汇报关系」自动推导（员工的直属上级 = 部门管理员），不单独配权限。

## 三、功能需求

### 3.1 底座：组织架构与账号（本期简述，沿用通用方案）

- FD-BASE-01：部门树形管理，用户挂部门，部门管理员即该部门审批人
- FD-BASE-02：账号由 HR 统一创建，员工首次登录强制改密；密码策略沿用公司规范（8-20 位含字母数字，90 天有效期）
- FD-BASE-03：员工入职日期、试用期标记（影响年假额度与考勤统计）

### 3.2 考勤管理（本期重点一）

**班次与考勤日历**

- FD-ATT-01：班次类型：固定班（09:00-18:00，午休 12:00-13:00）、弹性班（核心时段 10:00-16:00 + 每日满 8 小时）
- FD-ATT-02：考勤日历：默认周一至周五工作日、周六日休息；HR 可维护节假日与调休（法定假日标记为休息，调休上班日标记为工作日）
- FD-ATT-03：排班按部门设置，支持同部门多班次混合（如客服组含夜班）

**打卡**

- FD-ATT-04：每日可打上班卡 + 下班卡；一天内多次打卡，取**最早一次**为上班卡、**最晚一次**为下班卡
- FD-ATT-05：迟到判定：固定班 09:00 后打卡记迟到；弹性班 10:00 后进核心时段记迟到；早退判定对称
- FD-ATT-06：缺卡：有上班卡无下班卡（或反之）记「缺卡」，**缺卡 ≠ 旷工**，缺卡需走补卡流程
- FD-ATT-07：旷工判定：工作日全天无任何打卡记录且当日无已批准请假/出差，记旷工
- FD-ATT-08：夜班跨天：22:00-06:00 班次的考勤**归属上班打卡当天**
- FD-ATT-09：打卡限制：仅限公司 IP 段内打卡（远程打卡走「外勤打卡」并填备注，外勤打卡默认计入考勤但不计迟到早退判定，需直属上级知晓）
- FD-ATT-10：休息日/节假日打卡不产生考勤记录，不参与判定

**补卡**

- FD-ATT-11：员工可对缺卡日期发起补卡申请，说明原因，走审批流
- FD-ATT-12：每人每月补卡上限 3 次；补卡仅可补**近 7 天内**的记录，更早的需 HR 手工调整

**加班与调休**

- FD-ATT-13：加班需提前申请（关联审批流），审批通过后按实际打卡时间计算加班时长（取申请时长与打卡时长的较小者）
- FD-ATT-14：调休折算：工作日加班满 1 小时起计，按 1:1 折调休；休息日加班按 1:1 折算（Demo 简化，不做 1.5/2 倍法定倍率）
- FD-ATT-15：调休余额：加班累积、请假（调休假类型）扣减，余额可跨年清零（次年 4 月 30 日过期）

**考勤统计**

- FD-ATT-16：个人月度考勤报表：出勤/迟到/早退/缺卡/旷工/请假/出差天数汇总，明细可下钻
- FD-ATT-17：部门月度报表（HR、部门管理员可见），支持导出 Excel
- FD-ATT-18：统计口径：按自然月（1 日 0 点至月末 24 点），以「当月内已批准」的申请为准；月末审批中的单子不计入，下月报表修正

### 3.3 请假管理

- FD-LEA-01：假期类型：年假（额度按入职年份核定，如满 1 年 5 天、满 5 年 10 天）、事假（无薪）、病假、调休假、婚丧产等法定假（HR 录入）
- FD-LEA-02：时长粒度：0.5 天起，最小单位半天；起止时间自动计算时长（跨午休、跨休息日自动剔除非工作时段）
- FD-LEA-03：余额校验：年假/调休余额不足不允许提交；事假/病假不校验余额
- FD-LEA-04：时间重叠校验：与本人已存在的请假/出差时间重叠时拦截提交
- FD-LEA-05：销假：请假提前结束可发起销假，按实际请假时长返还余额
- FD-LEA-06：病假需事后补交材料（附件），HR 有权将无材料的病假改记事假

### 3.4 审批流（本期重点二，通用引擎）

**流程规则**

- FD-APR-01：统一审批流引擎，四类申请共用：请假、补卡、加班、报销
- FD-APR-02：默认审批链：申请人直属上级 → 部门管理员 →（按规则追加 HR / 财务）
- FD-APR-03：分级规则：
  - 请假：≤1 天一级（直属上级）；1-3 天两级（+部门管理员）；>3 天三级（+HR）
  - 报销：≤1000 元两级（直属上级 + 部门管理员）；1000-5000 元三级（+HR）；>5000 元四级（+财务负责人）
  - 补卡/加班：固定一级（直属上级）
- FD-APR-04：边界取「含头不含尾」：如请假恰好 1 天走一级，报销恰好 1000 元走两级

**状态机**

- FD-APR-05：单据状态：`草稿 → 待审批 → 审批中（多级流转）→ 已通过 / 已驳回 / 已撤回`
- FD-APR-06：撤回：仅在**下一级审批人尚未处理**前可撤回，撤回后单据回到草稿可修改重提
- FD-APR-07：驳回：任一级驳回则整个流程终止；申请人可修改后重新提交，重提生成新审批流，原驳回记录留痕
- FD-APR-08：审批人操作：通过 / 驳回（必填意见）/ 转交（转给同部门其他有审批权限的人）
- FD-APR-09：审批人缺席：直属上级为空或已离职，自动跳过该级并升级到部门管理员，审批记录标注「自动跳过」

**并发与时限**

- FD-APR-10：并发审批：两名审批人同时处理同一单据，先提交者生效，后提交者提示「该单据已被处理」
- FD-APR-11：超时提醒：待审批超过 24 小时，站内信提醒审批人（仅提醒，不自动通过）
- FD-APR-12：审批全程留痕：每级记录操作人、动作、时间、意见，不可篡改；审批中/已通过的单据**不可编辑、不可删除**

**特殊场景**

- FD-APR-13：审批人是申请人自己（如部门管理员给自己报销）：该级自动跳过，升级到上一级规则的下一级
- FD-APR-14：员工调岗/直属上级变更：进行中的单据仍按**发起时**的审批链走完，新发起的单按新架构

### 3.5 报销管理（本期重点三）

**报销单**

- FD-EXP-01：报销单字段：报销事由、费用类型（差旅/餐饮/办公用品/培训/其他）、明细行（日期、金额、说明、发票号、发票代码、附件）
- FD-EXP-02：明细行支持多行（上限 20 行），金额为总金额自动汇总
- FD-EXP-03：金额规则：每行金额 > 0，最多两位小数；单笔报销总额上限 20000 元；员工自然月累计上限 10000 元（含审批中）
- FD-EXP-04：发票防重：发票号全局唯一，同一发票号不允许出现在两张不同报销单中；同一单内重复也不允许
- FD-EXP-05：附件：jpg/png/pdf，单个 ≤ 5MB，每行明细最多 3 个附件，最多共 30 个
- FD-EXP-06：状态：`草稿 → 待审批 → 审批中 → 已通过 → 待打款 → 已打款`（驳回/撤回分支同审批流）；打款状态由财务单独操作
- FD-EXP-07：财务操作：审批全部通过后进入「待打款」；财务标记「已打款」（需填打款流水号）或「打款失败」（需填原因，退回待打款）
- FD-EXP-08：驳回后修改重提：仅可修改明细与事由，不允许更换费用类型规避分级规则
- FD-EXP-09：报销报表：财务/超管按月份、费用类型、部门统计，导出 Excel；导出上限 10000 条

**合规约束**

- FD-EXP-10：报销时效：费用发生日期距提交超过 90 天，拦截并提示（跨年发票需单独走线下）
- FD-EXP-11：删除规则：仅草稿、已撤回状态可删除；已驳回单据保留 90 天后自动清理

### 3.6 站内信与日志（简述）

- FD-MSG-01：通知场景：审批结果（通过/驳回）、超时提醒、打款结果、余额调整
- FD-AUD-01：审计日志：审批动作、打款、假勤手工调整（HR 修正考勤、调整余额）均记敏感日志，不可删改

## 四、非功能需求

- NF-01：兼容 Chrome / Edge 最新两版 + 手机浏览器（响应式）
- NF-02：月度考勤报表（200 人 × 31 天）生成 ≤ 5s
- NF-03：**打卡高峰**：工作日 08:50-09:10 集中打卡，100 并发打卡请求成功率 100%，单次响应 ≤ 2s
- NF-04：密码 MD5 传输（Demo 级要求）
- NF-05：所有提交类接口幂等防重，重复点击不产生重复单据

## 五、范围边界（本期不做）

- 不做原生 App、不做钉钉/企微对接
- 不做薪资计算（考勤数据只导出，不联动算薪）
- 不做地理围栏定位打卡（仅 IP 段限制 + 外勤打卡）
- 不做发票 OCR 自动识别（发票信息手填）
- 不做多级会签（任一级通过即流转，不做多人会签）
- 不做法定加班倍率（1.5/2/3 倍）与个税
